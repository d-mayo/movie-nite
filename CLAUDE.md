# movie-nite

## Purpose
A web app for the FFF movie-night group to pick tonight's film: viewers nominate films found through TMDB, and a weighted, editable wheel picks what to watch through the night.
A static single-page app (React, TypeScript, Vite) hosted on GitHub Pages, with no backend.

## Commands
<!-- covers: package.json, .github/workflows/*.yml; verified: 2026-10-10 -->
- Run tests: `npm test`
- Lint: `npm run lint`
- Dev server: `npm run dev` (serves at http://localhost:5173/movie-nite/)
- Dev server on the network, for a phone: `npm run dev:lan` (see Gotchas)
- Build: `npm run build`
- Full check (what CI runs): `npm ci && npm run lint && npm test && npm run build`

## Layout
<!-- covers: src/**, public/**, .github/workflows/*.yml; verified: 2026-10-09 -->
- `src/`: the React app: `src/main.tsx` builds the store on the `localStorage` persistence and mounts `src/App.tsx`; `src/assets/` holds the TMDB logo and the Movie Nite logo set (`src/assets/logo/`: the six final SVGs, including the simplified square M-and-reel icon in light and dark, plus `src/assets/logo/old-iterations/`, the earlier designs kept for reference), which feed the site banner in `src/App.tsx` (its TMDB attribution footer shows only on the token prompt) and the README logo block, and which `src/assets/logo.test.ts` checks (including that README block); `src/test/setup.ts` is the Vitest setup
- `src/index.css`: the shared look: color (the logo's six greys plus one `--danger`, and the `--film-*` tokens: the reel's stock, cream and steel greys, defined once on `:root` and the same in light and dark, used only by the wheel, its Spin button, the flicker and the reveal's frame, whose reveal block redefines the color tokens to their dark values and so looks the same in both schemes), spacing, radius and shadow tokens on `:root`, redefined under `prefers-color-scheme: dark`, and base styles for bare controls inside `:where()` (zero specificity, so the spin button and other class rules still win) with the `primary`, `quiet` and `danger` button variants and the `card` class; `src/styles.test.ts` checks its palette (the film tokens apart) and WCAG contrast, and the film tokens' values and placement; the shared control rules (the inset-card, card-head, stepper, slider and switch classes, the visually-hidden class and the range input) live there too; component layout rules live in `src/App.css`
- `public/`: files Vite serves as-is under the base path; `public/favicon.svg` is the site favicon, a copy of `src/assets/logo/logo-icon-light.svg` that `src/assets/logo.test.ts` keeps identical
- `src/sound/`: the sound engine, React-free (`src/sound/engine.ts`: one `AudioContext` made and resumed on the first gesture anywhere in the document, the projector files decoded then, buses effects/music → master gain → destination driven by the sound settings, the projector's switch-on, the motor hum following the wheel's speed and its switch-off, and the synthesized pin ticks, spaced at least 30 ms apart on the audio clock (a tick asked for too soon waits for the next slot, so a fast wheel ticks steadily); a silent engine where there is no Web Audio, and every call a no-op) and `src/sound/browser.ts` (the browser's Web Audio and the MP3s); `src/main.tsx` builds it and passes it down as the optional `sound` prop (`App` → `WheelPanel` → `useWheelMotion`, which drives it from its one loop during a spin only, never while idle); `src/assets/sound/` holds the three projector MP3s and a README with their cut and loop points, the original WAVs live in the gitignored `sound-sources/`; `src/test/fakeAudio.ts` is the recording fake context for the engine tests
- `src/state/`: the serializable app state (`src/state/model.ts` pure rules, including the settings (the TMDB token, `viewersHidden`, whether the viewer pane is slid away, and `settings.wheel`, the global wheel settings: One per viewer, the wildcard count and weight, the default slices and weight, and the spin length and intensity, and the sound settings (Music and Effects switches and a 0 to 100 Volume), all kept by New night) and the roster (capped at 12 viewers, each with a unique preset color) and the night rules (the night's `spun` and `holdoverDismissed` flags: the first spin of a night clears the held film, which New night otherwise keeps; who is on the wheel, recording a Watch or Too long, ending and restarting a night, and the night's `adjustments`, the slices or weight the host set for one viewer tonight: New night clears them, Remove from roster drops them, and the wheel is derived from them rather than saved), `src/state/persistence.ts` the `Persistence` interface and its `localStorage` and in-memory versions, `src/state/store.ts` the Zustand store and React hook, `src/state/id.ts` new ids that also work on plain-HTTP origins); only `src/state/persistence.ts` touches `localStorage`
- `src/tmdb/`: the TMDB client (injectable `fetch`, `TmdbAuthError` on 401)
- `src/wheel/`: the pure wheel rules, no React or storage: `src/wheel/layout.ts` (the `Slice` type and slice arcs), `src/wheel/draw.ts` (weighted draw and rest rotation: the rest point falls anywhere in the slice but a margin of 1.2° or a quarter of a narrow slice at each edge), `src/wheel/motion.ts` (the spin's path as a pure function of time: wind-up, then a glide that creeps to a stop on the rest point, plus the idle drift's speed easing), `src/wheel/pins.ts` (the pins at the slice edges, thinned to at least 2° apart round the wheel, the direction of motion, `pinExits` (how many pins slipped off the tongue's tip over a frame, for the pin ticks), the flapper's bend (a pin pushes the tongue along from where it touches until it slips off at 30°, swept over each frame so a fast wheel bends it fully) and its damped spring, all pure), `src/wheel/reveal.ts` (finish window, runtime and synopsis text), `src/wheel/edit.ts` (the wheel settings and their factory values, the validity checks, `spinPlan` (the spin's duration and full turns, with the reduced-motion override), a viewer's effective slices and weight, and `deriveSlices`, which builds the wheel from the viewers on it in roster order, with the even spread and the wildcards spaced among the slices), `src/wheel/colors.ts` (the 12 viewer color presets, the `mixColor` helper that builds the wedge gradients, and the load-time rule that fills in missing or duplicate colors), `src/wheel/wedges.ts` (slices resolved to names, colors and nominations), plus `src/wheel/reducedMotion.ts` (the one browser check, `prefers-reduced-motion`, and a change listener, both guarded for jsdom)
- `src/components/`: token prompt, the viewer pane (`src/components/NightSetup.tsx`: one `src/components/ViewerCell.tsx` per roster viewer, ordered on the wheel, won tonight, then away; an eye toggle, a header that opens the cell on hover (`src/components/canHover.ts` reads the hover query), tap or Enter/Space, and, except for an away viewer, an open body that is a panel joined to the cell (placed by `ViewerCell` left of the cell at 900 px and up, above it below that) with the film control (`src/components/NominationSearch.tsx`: the poster with an X that removes the film, or the search), the `ColorPicker` swatch (`src/components/ColorPicker.tsx`, a popover of the 12 presets), an inset card (the inset-card class) holding the Slices `Stepper` (`src/components/Stepper.tsx`: −/+ buttons and the value over a 12-tick bar, 1 to 12; ticks are pointer-only, keys work anywhere in it, at a limit a button is `aria-disabled` so focus stays, and the `disabled` prop makes the whole stepper inert and dimmed: native `disabled` buttons, no keys or tick clicks) and the Weight `Slider` (`src/components/Slider.tsx`: label and value on one row, a filled track under them, an optional `format`) and a ⋯ menu with Reset slices and weight (enabled while the viewer has an adjustment tonight) and a confirmed Remove from roster; a viewer with any adjustment, away or won included, shows an asterisk after their name (title and accessible text "Adjusted tonight"); the pane's header row has the ⋯ menu and a Hide viewers button (outside the spin-locked fieldset, so it works during a spin; `src/App.tsx` renders the Show viewers tab at the screen's right edge while hidden, and a press moves focus to the opposite control); the pane holds the one open cell, the hover timers, the stay-open rules and the spin lock, and has its own ⋯ menu that resets every viewer's slices and weight), nomination search and the reusable film search it is built on (`src/components/FilmSearch.tsx`), the banner's night controls (`src/components/NightControls.tsx`: End night with its confirmation `<dialog>`, New night, and the ⚙ Popover menu holding Wheel settings (first, disabled once the night has ended) and Change TMDB token; the banner has no Wheel settings button, and ⚙ takes an `active` class while the popover is open), the Night over summary (`src/components/NightOver.tsx`), the held film's non-modal corner card and its banner chip (`src/components/HeldFilm.tsx`: before a night's first spin the card reads "From last session:" with one Acknowledge/Watch button that clears the film for good; after it, "Watch next session:" with one Dismiss button that shrinks it to a "Next: <title>" chip, which brings it back; focus moves only on those presses), the Wheel settings popover (`src/components/WheelEditor.tsx`, a modal `<dialog>` named by `aria-label`, with no title or Done button and a transparent backdrop, hung under the ⚙ button with focus on the dialog itself; it closes on Escape, on a press that starts outside it, and, on hover devices, 150 ms (`closeDelayMs` in `src/components/canHover.ts`, shared with the viewer cells and the ⚙ menu, which also closes that way and lists its items vertically) after the pointer leaves it once it has been inside; four inset cards whose controls apply as they change: Wildcards (the One per viewer switch, a count stepper that shows the live viewer count and is inert while the switch is on, and the wildcard weight slider), Spin (Length and Intensity sliders), Viewer Defaults (slices and weight per viewer) and Sound (Music and Effects switches and a Volume slider); the popover is one column and scrolls when it runs out of height; a Restore All Defaults button at the popover's bottom opens a confirmation and puts every global wheel setting back to its factory value, leaving viewers' adjustments; the per-viewer controls live in the cells), the wheel (`src/components/Wheel.tsx`: soft radial-gradient wedges (one gradient per distinct viewer color, ids from `useId`) with posters fading in, white labels on a dark scrim, a fixed gloss and the pointer; `src/components/Reel.tsx`, the film strip with a frame per slice, a pin at each slice edge that `pinAngles` keeps and 288 sprocket holes, drawn inside the rotating group, which is turned by `src/components/useWheelMotion.ts`: one `requestAnimationFrame` loop drifts the wheel while idle and plays the spin path, writing the angle to the group's and the Spin hub's `transform` through refs, and the pointer's flapper (a steel tongue on a pivot screw, drawn outside the turning group and bent by the pins as they pass, forward, backward in the wind-up, and while idle) the same way, never React state, so neither causes a render per frame), the spin (`src/components/WheelPanel.tsx`, whose Spin button is the reel's hub, a turning steel disc under an upright SPIN label in Bebas Neue (the @fontsource/bebas-neue package, bundled), and which, on landing, plays the projector flicker over the whole screen (a fixed overlay) and opens the reveal 0.65 s later (at once with reduced motion, or with the test-only `spinMs`); it portals its "waiting for" message into a slot `src/App.tsx` renders under the viewer pane, or fixed at the screen's bottom while the pane is hidden) and the reveal (`src/components/Reveal.tsx`: a frame of the film print, black stock with cream sprocket rails down both sides (drawn by masked pseudo-elements on the inner film element, which grows with the scrolling content), the poster on the left and on the right a dot in the viewer's color with "Now showing", the Bebas Neue title, year, byline, runtime and finish window and synopsis; a wildcard before its pick uses the same frame with a "?" poster, a `--film-steel-light` dot and the search; Watch is the main button, cream on stock, and Save for Next Week, small and underlined below it, asks before replacing a film already saved this night; the frame threads in with a CSS animation (the reveal-thread class, left off under reduced motion), and the app has no animation package)
- `.github/workflows/`: `.github/workflows/ci.yml` runs lint, test and build on pull requests and pushes to `main`, and deploys to GitHub Pages on pushes to `main`

## Conventions
- Branches are `<type>/<issue>-<slug>`; every change goes through a PR that says `Closes #<issue>`; merges are squash-only.

## Gotchas
- Vite's `base` is `/movie-nite/`, so local URLs and the live site are under that path (http://localhost:5173/movie-nite/, not the root).
- Node 22 is pinned in `.nvmrc`; CI uses it, so a newer local Node can hide a CI failure.
- Deploys happen only after a merge to `main` (the `github-pages` environment accepts only the default branch), so a live-site check can't be done before merge; check PRs locally with `npm run build` and `npm run preview`, and write live-site checks in plans as post-merge follow-ups.
- On Windows, stop any running `npm run dev` before `npm ci`: the dev server locks a native file, so `npm ci` fails and leaves `node_modules` half-removed. If PowerShell blocks the npm script, run npm.cmd instead.
- Vite adds `base` to files in `public/` itself, so link them from `index.html` with a root path (`/favicon.svg`); `%BASE_URL%favicon.svg` doubles the prefix to `/movie-nite/movie-nite/favicon.svg`.
- To test from a phone, run `npm run dev:lan` and open the Network URL it prints (it ends in `/movie-nite/`); the phone must be on the same Wi-Fi, and Windows Firewall may need to allow Node. Over plain HTTP, browsers hide secure-origin-only APIs such as `crypto.randomUUID`, so use `src/state/id.ts` for ids and avoid such APIs.
- The sound engine unlocks on `pointerdown`, `pointerup`, `keydown` and `touchend` (iOS counts a touch's activation only on its end) and keeps retrying until the context is running; jsdom has no Web Audio, so tests inject a fake through the `sound` prop or `createSound`. A click made from script is no gesture, so in the Browser pane press with a real click; the pane's frames only advance while it paints, so a spin there runs long and its ticks come sparse.
- Vitest turns every CSS import, `?raw` included, into an empty string, so `vite.config.ts` sets `test.css.include` to `/index.css/` (unanchored: the `?raw` suffix is part of the module id) for `src/styles.test.ts`; jsdom still applies no CSS.
- jsdom has neither `HTMLDialogElement.showModal` nor the Popover API (and hides every closed `[popover]`), so `src/test/setup.ts` stubs `showModal`/`close` and `showPopover`/`hidePopover`/`togglePopover` plus `popovertarget` clicks; a popover shows by an inline `display: block`, not `:popover-open`.
- The card class sets `display`, which beats the browser's own hiding of a closed `[popover]`; a popover that uses the card class needs its own `:not(:popover-open) { display: none }` rule (see the color picker in `src/App.css`).
- Hiding the viewer pane (900 px and up) is CSS only: the viewers-hidden class on the night wrapper (in `src/App.css`) collapses the grid column, slides the setup column out with `translate` and sets `visibility: hidden` after the slide (a delayed transition) to drop it from the tab order; the wrapper has `overflow-x: clip` so the slid-out pane adds no scrollbar. Browser-pane transitions only advance while the pane is painting, so read computed styles after a screenshot.
- jsdom applies no CSS, so a cell panel's layout (its fixed placement, borders and the results list over it) can only be checked in a real browser; the panel is placed in `ViewerCell` when `window.innerWidth` is at least 900, matching the breakpoint in `src/App.css`, and clears `bottom` because the narrow rule sets it.
- A modal dialog's `::backdrop` covers the viewport and its events target the dialog element itself, so the Wheel settings popover finds the pointer leaving by comparing positions with its rectangle, and absorbs an outside press by staying open until its `click` (the press's pointerup and click then land on the backdrop, not on what lies beneath); this breaks if the backdrop ever gets `pointer-events: none`.
- A nowrap flex row takes its minimum width from its items' intrinsic widths (a text input's default width, say), so a row inside the narrow cell panel needs `min-width: 0` or it pushes its last item past the panel's edge (see the cell-main rule in `src/App.css`).
- The Browser pane runs `requestAnimationFrame` only while it is painting (a hidden window stops it), so check the wheel's motion with screenshots between readings and leave smoothness to a real browser; jsdom's `requestAnimationFrame` runs at about 30 fps, enough for the drift tests on real time.
- Stub `matchMedia` in tests with `vi.stubGlobal` and undo it with `vi.unstubAllGlobals()`: restoring a saved property descriptor left the stub in place and leaked into later tests in the file.
- The rotating group must stay the wheel svg's first `<g>` child (a `<defs>` before it is fine): tests read the angle from `svg.wheel > g`. The reel's fixed film colors reach the SVG through CSS classes in `src/App.css`; colors derived from a viewer's color are attributes computed in TypeScript.
