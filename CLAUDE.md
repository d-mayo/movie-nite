# movie-nite

## Purpose
A web app for the FFF movie-night group to pick tonight's film: viewers nominate films found through TMDB, and a weighted, editable wheel picks what to watch through the night.
A static single-page app (React, TypeScript, Vite) hosted on GitHub Pages, with no backend.

## Commands
<!-- covers: package.json, .github/workflows/*.yml; verified: 2026-10-08 -->
- Run tests: `npm test`
- Lint: `npm run lint`
- Dev server: `npm run dev` (serves at http://localhost:5173/movie-nite/)
- Dev server on the network, for a phone: `npm run dev:lan` (see Gotchas)
- Build: `npm run build`
- Full check (what CI runs): `npm ci && npm run lint && npm test && npm run build`

## Layout
<!-- covers: src/**, public/**, .github/workflows/*.yml; verified: 2026-10-07 -->
- `src/`: the React app: `src/main.tsx` builds the store on the `localStorage` persistence and mounts `src/App.tsx`; `src/assets/` holds the TMDB logo and the Movie Nite logo set (`src/assets/logo/`: the six final SVGs, including the simplified square M-and-reel icon in light and dark, plus `src/assets/logo/old-iterations/`, the earlier designs kept for reference), which feed the site banner in `src/App.tsx` (its TMDB attribution footer shows only on the token prompt) and the README logo block, and which `src/assets/logo.test.ts` checks (including that README block); `src/test/setup.ts` is the Vitest setup
- `src/index.css`: the shared look: color (the logo's six greys plus one `--danger`), spacing, radius and shadow tokens on `:root`, redefined under `prefers-color-scheme: dark`, and base styles for bare controls inside `:where()` (zero specificity, so the spin button and other class rules still win) with the `primary`, `quiet` and `danger` button variants and the `card` class; `src/styles.test.ts` checks its palette and WCAG contrast; component layout rules live in `src/App.css`
- `public/`: files Vite serves as-is under the base path; `public/favicon.svg` is the site favicon, a copy of `src/assets/logo/logo-icon-light.svg` that `src/assets/logo.test.ts` keeps identical
- `src/state/`: the serializable app state (`src/state/model.ts` pure rules, including the roster (capped at 12 viewers, each with a unique preset color) and the night rules (the night's `spun` and `holdoverDismissed` flags: the first spin of a night clears the held film, which New night otherwise keeps; who is on the wheel, recording a Watch or Too long, ending and restarting a night, and the wheel-editing actions that save the edited layout on `night.layout`), `src/state/persistence.ts` the `Persistence` interface and its `localStorage` and in-memory versions, `src/state/store.ts` the Zustand store and React hook, `src/state/id.ts` new ids that also work on plain-HTTP origins); only `src/state/persistence.ts` touches `localStorage`
- `src/tmdb/`: the TMDB client (injectable `fetch`, `TmdbAuthError` on 401)
- `src/wheel/`: the pure wheel rules, no React or storage: `src/wheel/layout.ts` (default layout and slice arcs), `src/wheel/draw.ts` (weighted draw and rest rotation), `src/wheel/reveal.ts` (finish window, runtime and synopsis text), `src/wheel/edit.ts` (the editable `WheelLayout`: even spread, weights up to 20, slice counts, the one weight all wildcards share, moving slices, viewers leaving and joining, and `normaliseLayout`, which converts older saved layouts), `src/wheel/colors.ts` (the 12 viewer color presets, WCAG contrast and black-or-white label text, and the load-time rule that fills in missing or duplicate colors), `src/wheel/wedges.ts` (slices resolved to names, colors and nominations), plus `src/wheel/reducedMotion.ts` (the one browser check, `prefers-reduced-motion`, guarded for jsdom)
- `src/components/`: token prompt, the viewer pane (`src/components/NightSetup.tsx`: one `src/components/ViewerCell.tsx` per roster viewer, ordered on the wheel, won tonight, then away; an eye toggle, a header that opens the cell on hover (`src/components/canHover.ts` reads the hover query), tap or Enter/Space, and, except for an away viewer, an open body that is a panel joined to the cell (placed by `ViewerCell` left of the cell at 900 px and up, above it below that) with the film control (`src/components/NominationSearch.tsx`: the poster with an X that removes the film, or the search), the `ColorPicker` swatch (`src/components/ColorPicker.tsx`, a popover of the 12 presets), the Slices and Weight `Slider`s (`src/components/Slider.tsx`) and a ⋯ menu with Reset slices and weight and a confirmed Remove from roster; the pane holds the one open cell, the hover timers, the stay-open rules and the spin lock, and has its own ⋯ menu that resets every viewer's slices and weight), nomination search and the reusable film search it is built on (`src/components/FilmSearch.tsx`), the banner's night controls (`src/components/NightControls.tsx`: Wheel settings, which opens the wheel editor as a popover under its button, End night with its confirmation `<dialog>`, New night, and the ⚙ Popover menu holding Change TMDB token), the Night over summary (`src/components/NightOver.tsx`), the held film's non-modal corner card and its banner chip (`src/components/HeldFilm.tsx`: before a night's first spin the card reads "From last session:" with one Acknowledge/Watch button that clears the film for good; after it, "Watch next session:" with one Dismiss button that shrinks it to a "Next: <title>" chip, which brings it back; focus moves only on those presses), the Wheel settings popover (`src/components/WheelEditor.tsx`, a modal `<dialog>` with a transparent backdrop, placed under the banner button that opens it; the wildcard weight slider that applies as it moves, wildcards, and dnd-kit drag to reorder; the per-viewer sliders live in the cells), the wheel (`src/components/Wheel.tsx`), the spin (`src/components/WheelPanel.tsx`) and the reveal (`src/components/Reveal.tsx`: Watch is the main button, and Save for Next Week, small below it, asks before replacing a film already saved this night)
- `.github/workflows/`: `.github/workflows/ci.yml` runs lint, test and build on pull requests and pushes to `main`, and deploys to GitHub Pages on pushes to `main`

## Conventions
- Branches are `<type>/<issue>-<slug>`; every change goes through a PR that says `Closes #<issue>`; merges are squash-only.

## Gotchas
- Vite's `base` is `/movie-nite/`, so local URLs and the live site are under that path (http://localhost:5173/movie-nite/, not the root).
- Node 22 is pinned in `.nvmrc`; CI uses it, so a newer local Node can hide a CI failure.
- Deploys happen only after a merge to `main` (the `github-pages` environment accepts only the default branch), so a live-site check can't be done before merge; check PRs locally with `npm run build` and `npm run preview`, and write live-site checks in plans as post-merge follow-ups.
- On Windows, stop any running `npm run dev` before `npm ci`: the dev server locks a native file, so `npm ci` fails and leaves `node_modules` half-removed. If PowerShell blocks the npm script, run npm.cmd instead.
- Vite adds `base` to files in `public/` itself, so link them from `index.html` with a root path (`/favicon.svg`); `%BASE_URL%favicon.svg` doubles the prefix to `/movie-nite/movie-nite/favicon.svg`.
- To test from a phone, run `npm run dev:lan` and open the Network URL it prints (it ends in `/movie-nite/`); the phone must be on the same Wi-Fi, and Windows Firewall may need to allow Node. Over plain HTTP, browsers hide secure-origin-only APIs such as `crypto.randomUUID`, so use `src/state/id.ts` for ids and avoid such APIs.
- Vitest turns every CSS import, `?raw` included, into an empty string, so `vite.config.ts` sets `test.css.include` to `/index.css/` (unanchored: the `?raw` suffix is part of the module id) for `src/styles.test.ts`; jsdom still applies no CSS.
- jsdom has neither `HTMLDialogElement.showModal` nor the Popover API (and hides every closed `[popover]`), so `src/test/setup.ts` stubs `showModal`/`close` and `showPopover`/`hidePopover`/`togglePopover` plus `popovertarget` clicks; a popover shows by an inline `display: block`, not `:popover-open`.
- The card class sets `display`, which beats the browser's own hiding of a closed `[popover]`; a popover that uses the card class needs its own `:not(:popover-open) { display: none }` rule (see the color picker in `src/App.css`).
- jsdom applies no CSS, so a cell panel's layout (its fixed placement, borders and the results list over it) can only be checked in a real browser; the panel is placed in `ViewerCell` when `window.innerWidth` is at least 900, matching the breakpoint in `src/App.css`, and clears `bottom` because the narrow rule sets it.
