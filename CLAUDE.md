# movie-nite

## Purpose
A web app for the FFF movie-night group to pick tonight's film: viewers nominate films found through TMDB, and a weighted, editable wheel picks what to watch through the night.
A static single-page app (React, TypeScript, Vite) hosted on GitHub Pages, with one small Cloudflare Worker in `worker/` that holds the TMDB token and relays the app's TMDB calls.

## Commands
<!-- covers: package.json, .github/workflows/*.yml; verified: 2026-10-24 -->
- Run tests: `npm test`
- Lint: `npm run lint`
- Dev server: `npm run dev` (serves at http://localhost:5173/movie-nite/)
- Dev server on the network, for a phone: `npm run dev:lan` (see Gotchas)
- Worker dev server (search needs it): `npm run dev:worker` (serves at http://localhost:8787; needs `worker/.dev.vars`, see `worker/README.md`)
- Build: `npm run build`
- Full check (what CI runs): `npm ci && npm run lint && npm test && npm run build`

## Conventions
- Branches are `<type>/<issue>-<slug>`; every change goes through a PR that says `Closes #<issue>`; merges are squash-only.

## Gotchas
- The Worker deploys only after a merge to `main` too (before the site), so the live `/lb/probe` and a live search check are post-merge; the rate-limit binding is local-only under `wrangler dev`. `worker/.dev.vars` (gitignored) holds the token for local runs, and a phone on `npm run dev:lan` also needs port 8787 allowed through the firewall.
- Vite's `base` is `/movie-nite/`, so local URLs and the live site are under that path (http://localhost:5173/movie-nite/, not the root).
- Node 22 is pinned in `.nvmrc`; CI uses it, so a newer local Node can hide a CI failure.
- Deploys happen only after a merge to `main` (the `github-pages` environment accepts only the default branch), so a live-site check can't be done before merge; check PRs locally with `npm run build` and `npm run preview`, and write live-site checks in plans as post-merge follow-ups.
- On Windows, stop any running `npm run dev` or `npm run dev:worker` before `npm ci`: the dev server (and wrangler's esbuild and workerd) lock native files, so `npm ci` fails and leaves `node_modules` half-removed. If PowerShell blocks the npm script, run npm.cmd instead.
- Vite adds `base` to files in `public/` itself, so link them from `index.html` with a root path (`/favicon.svg`); `%BASE_URL%favicon.svg` doubles the prefix to `/movie-nite/movie-nite/favicon.svg`.
- To test from a phone, run `npm run dev:lan` and open the Network URL it prints (it ends in `/movie-nite/`); the phone must be on the same Wi-Fi, and Windows Firewall may need to allow Node. Over plain HTTP, browsers hide secure-origin-only APIs such as `crypto.randomUUID`, so use `src/state/id.ts` for ids and avoid such APIs.
- The sound engine unlocks on `pointerdown`, `pointerup`, `keydown` and `touchend` (iOS counts a touch's activation only on its end) and keeps retrying until the context is running; jsdom has no Web Audio, so tests inject a fake through the `sound` prop or `createSound`. A click made from script is no gesture, so in the Browser pane press with a real click; the pane's frames only advance while it paints, so a spin there runs long and its ticks come sparse.
- Vitest turns every CSS import, `?raw` included, into an empty string, so `vite.config.ts` sets `test.css.include` to `/index\.css/` and `/App\.css\?raw/` (unanchored: the `?raw` suffix is part of the module id; a component's plain import of App.css stays empty, so no other test sees its rules) for `src/styles.test.ts`, which also reads `src/App.css` for the reduced-motion rules and the card faces' contrast; jsdom still applies no CSS.
- jsdom has neither `HTMLDialogElement.showModal` nor the Popover API (and hides every closed `[popover]`), so `src/test/setup.ts` stubs `showModal`/`close` and `showPopover`/`hidePopover`/`togglePopover` plus `popovertarget` clicks; a popover shows by an inline `display: block`, not `:popover-open`. The stub handles no Escape or light dismiss, so the add-viewer popup handles Escape itself, and its + carries no `popovertarget` while the roster is full.
- The card class sets `display`, which beats the browser's own hiding of a closed `[popover]`; a popover that uses the card class needs its own `:not(:popover-open) { display: none }` rule (see the color picker in `src/App.css`).
- Hiding the viewer pane (900 px and up) is CSS only: the viewers-hidden class on the night wrapper (in `src/App.css`) collapses the grid column, slides the setup column out with `translate` and sets `visibility: hidden` after the slide (a delayed transition) to drop it from the tab order; the wrapper has `overflow-x: clip` so the slid-out pane adds no scrollbar. Browser-pane transitions only advance while the pane is painting, so read computed styles after a screenshot.
- jsdom applies no CSS, so a cell panel's layout (its fixed placement, borders and the results list over it) can only be checked in a real browser; the panel is placed in `ViewerCell` when `window.innerWidth` is at least 900, matching the breakpoint in `src/App.css`, and clears `bottom` because the narrow rule sets it.
- A modal dialog's `::backdrop` covers the viewport and its events target the dialog element itself, so the Wheel settings popover finds the pointer leaving by comparing positions with its rectangle, and absorbs an outside press by staying open until its `click` (the press's pointerup and click then land on the backdrop, not on what lies beneath); this breaks if the backdrop ever gets `pointer-events: none`.
- A nowrap flex row takes its minimum width from its items' intrinsic widths (a text input's default width, say), so a row inside the narrow cell panel needs `min-width: 0` or it pushes its last item past the panel's edge (see the cell-main rule in `src/App.css`).
- The Browser pane runs `requestAnimationFrame` only while it is painting (a hidden window stops it), so check the wheel's motion with screenshots between readings and leave smoothness to a real browser; jsdom's `requestAnimationFrame` runs at about 30 fps, enough for the drift tests on real time.
- Stub `matchMedia` in tests with `vi.stubGlobal` and undo it with `vi.unstubAllGlobals()`: restoring a saved property descriptor left the stub in place and leaked into later tests in the file.
- The rotating group must stay the wheel svg's first `<g>` child (a `<defs>` before it is fine): tests read the angle from `svg.wheel > g`. The reel's fixed film colors reach the SVG through CSS classes in `src/App.css`; colors derived from a viewer's color are attributes computed in TypeScript.
- The path lint treats every backticked token in this file as a path, so write CSS class names and selectors without backticks.
- The music, stinger and applause decode on the first gesture like the projector files, so a very first spin pressed as that gesture plays no loop (the stinger and applause still play if decoded by the landing); the dip, bed and fade are gain ramps on the audio clock, and the fade is exponential to sound even, so tests read which method set each value (the fake param records it) rather than the final number.
- Opening the app with debug in the query string (for example /movie-nite/?debug) shows an unsaved Force close calls checkbox under the wheel; use it to test a close call at will, and ordinary spins are unchanged without the flag; a Force countdowns checkbox there forces a countdown on every spin, a Force wildcards checkbox there makes every main spin draw a wildcard when the wheel has one (to reach the wildcard wheel at will; the Force checkboxes stay on for the wildcard wheel's own spin), a Force card select there (Random deal by default) makes the wildcard wheel's deal eight copies of the chosen card whenever that card is eligible, whatever the card switches say (the landing also opens the wildcard wheel for it when every card is switched off; the FFF cards are listed there, and forced, only while they are unlocked, so `?debug` alone never shows them), so Blind Spin, always eligible, can be tested at will (pair it with Force wildcards), a Force catches checkbox there does the same for a catch (with both checked, a close call wins whenever the drawn slice has a zone), and in tests the catch's tick is told from the pass ticks by its fixed share (catchTickShare), since a test-length spin is too fast for their order to show.
- A close call's bend rests the pointer's line just past a pin, in the neighbor's angles, while the flapper still points at the drawn film, so the winner is always the drawn slice kept in the spin state, never read back from where the wheel stops; `src/wheel/closeCall.ts` holds the zones.
- A close call's zoom scales a wrapper over the whole screen: the banner (opaque, z-index 5) and the viewer pane (3) stay above the vignette (2) and the zoomed wheel (1), and the root element stops scrolling with a stable scrollbar gutter while it runs, so a new fixed overlay needs a z-index that fits.
- The dev server can cache an empty or half-written module for a file it read while it was being rewritten (a script that writes a file in several steps does this), which blanks the page with a console error (no default export, or a name that is not defined) or leaves a component running old logic, such as cans that stall; touching the file refreshes it.
- Letterboxd challenges (403 "Just a moment") every check from `npm run dev:worker` on a home IP, though not the deployed Worker, so a username that never leaves pending locally is that, not a bug: for local Letterboxd work run `npm run dev:worker -- --remote` (it needs a wrangler login and runs on Cloudflare's edge, and port 8787 must be free).
- The Letterboxd username field carries `data-bwignore`, `data-1p-ignore`, `data-lpignore`, the name `lb-profile` and a label and placeholder without the word username, because Firefox and Bitwarden offered a login on it; keep "username" out of its label, name and placeholder.
- Letterboxd answers a private watchlist with the same 403 "classified" page it uses for a block, so the Worker reads any 403 that is not a bot challenge ("Just a moment", cf-chl) as private; a real block on the watchlist route therefore shows as "private" until it clears.
- `src/ci.test.ts` reads `.github/workflows/ci.yml` for `
  job:
`, so on a Windows checkout where git gives that file CRLF its 3 tests fail without any code being wrong; the real CI (LF) passes them.
